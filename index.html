Getting started

Vault Fields adds restricted fields to Jira issues. Values are stored encrypted inside the app on Atlassian's Forge platform and are never written to Jira's issue data, so only the people your rules allow can see them.

1. Create a restricted field

Jira administrators open Jira settings → Apps → Vault Fields and select Add field.

  1. Enter a field name and choose a type: Text, Number, Date or Dropdown.
  2. For a Dropdown, list the options separated by commas.
  3. Choose projects, or leave the list empty to apply the field to every project.
  4. Under Who can edit, tick Project lead and/or enter groups, project roles or users.
  5. Under Who can view, add people who should read the value without changing it.
  6. Select Save field. Group and role names are checked against Jira, so a typo is reported straight away.

2. Use the field on an issue

Open an issue and expand Restricted fields in the right-hand panel. Editors select Edit, change values and select Save. Viewers see values read-only. Everyone else sees nothing, including the field's name.

Who counts as an editor or viewer

Each request is checked on the server: the person must be able to open the issue in Jira, and must match a rule by user, group, project role or project lead. Access follows Jira's own permissions and issue security levels.

What Vault Fields does not do, by design

  • Restricted values are not searchable with JQL and do not appear in filters, boards, dashboards, exports, notifications, webhooks or the Jira REST API.
  • Jira administrators configure fields but do not see values unless a field's rules include them.
  • A Jira project lead is not automatically in the project's Administrators role. Use the Project lead option to include the lead.
  • If the subscription lapses, values stay readable for allowed people. Editing is paused until it is renewed.

Privacy policy

Last updated 22 October 2026

Vault Fields is developed by an independent developer based in Ukraine. Contact details are under Support.

What the app stores

  • Field definitions and access rules created by your Jira administrators.
  • Values entered into restricted fields.
  • A change log of who changed which field and when: Atlassian account ID, field ID and timestamp. The change log never contains values.

The app stores Atlassian account IDs only. It does not store names, email addresses or IP addresses.

Where it is stored

All data stays in Atlassian-hosted Forge storage. Field values use Forge's encrypted secret storage. We operate no servers, and the app sends no data outside Atlassian.

Who can access it

Values are shown only to users allowed by your administrators' rules, after the app checks their access with Jira. The developer has no access to your data and does not process it for any purpose.

Retention and deletion

Values and change-log entries are deleted when their issue is deleted. The change log keeps the latest 200 entries per issue. To have all app data for your site deleted, contact support.

Your role under GDPR

You, the customer, are the controller of the data in your Jira site. Where the developer is considered a processor, a Data Processing Addendum is available on request.
